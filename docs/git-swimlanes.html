git swimlanes

colori deterministici per nome · ogni colonna = un branch, etichettato
git --no-pager -c core.quotepath=false log --all --date-order --name-status --pretty=format:"%H|%P|%D|%an|%ad|%s" --date=short > git-history.txt
Funziona offline, in locale, senza inviare nulla.

commit
Perché funziona. Git memorizza il nome del branch solo sul suo tip (il ref): i commit storici non sanno a quale ramo appartengono. Qui ogni branch reclama la propria corsia risalendo la catena del first-parent dal suo tip — l'euristica standard, resa stabile: una corsia fissa per ramo, con etichetta. Il colore deriva solo dal nome (hash → tonalità): lo stesso branch ha sempre lo stesso colore, in ogni repo e ad ogni apertura. I merge sono dischi a ciambella; le pillole mostrano dove si trova ora ogni ref.

PR rilevate dal messaggio. Una PR non è un oggetto Git: la cerco nei messaggi di commit (⇲ PR #id, alone azzurro sul nodo). Riconosco Merged PR <id>: (Azure DevOps), Merge pull request #<id> (GitHub), !<id> (GitLab), il suffisso (#<id>) degli squash. Bordo tratteggiato = squash. Se il team usa il rebase in completamento PR, la PR sparisce del tutto dalla history: nessuna traccia, serve l'API della forge.

File modificati. Clicca una riga per aprire/chiudere l'elenco dei file (il grafo si allarga sotto al nodo, le corsie restano allineate); clicca un file per aprirne il diff. Servono i dati di --name-status nel log: il comando suggerito li include già. Il diff vero arriva dal tuo host via git show <hash> -- <file>. I merge non mostrano file di default — è Git, non un limite della vista.
